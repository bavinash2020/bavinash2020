## 1. INTRODUCTION
OYD (Own Your Driver) is a premium driver hiring web application designed to bring a high-quality user experience to outstation and local driver bookings. The project aims to bridge the gap between car owners and high-quality, verified professional drivers through a seamless, visually enhanced digital interface.

The application primarily focuses on user experience, offering a sleek, glassmorphism-themed responsive design where users can browse drivers, verify documents, and manage their trips. It solves the common problem of unverified drivers and inconsistent pricing by utilizing modern web technologies.

### 1.1 Purpose
The purpose of this project is to develop a functional prototype of a Driver Hiring platform frontend that demonstrates proficiency in modern web development standards (React 18, TypeScript, Vite) and user interface design principles.

### 1.2 Scope
The scope includes the development of the client-side interface, including:
- Home Page with Dynamic Typewriter Effects
- Role-based Authentication (Customer, Driver, Admin)
- Secure OTP Login using Fast2SMS API
- Customer Booking Portal & Driver Discovery
- Admin Dashboard for Document Verification
- Responsive Design for Mobile and Desktop

<div class="page-break"></div>

## 2. SYSTEM ANALYSIS
The system is designed as a Single Page Application (SPA) using React Router DOM. It relies on the client-side browser to handle logic such as route protection, component rendering, and session state management.

### 2.1 Existing System
Traditional driver hiring often requires negotiating with local taxi stands or unverified informal networks. Existing web solutions can sometimes be cluttered or lack strict verification protocols.

### 2.2 Proposed System
The proposed system automates the selection and booking process. It provides instant visual feedback (animations, booking updates) and ensures data persistence, while implementing a strict Admin-verification queue for driver documents (Aadhaar, License).

## 3. LITERATURE SURVEY
A study of existing successful mobility platforms like Uber, Ola, and local driver aggregators reveals that User Interface (UI) and Trust/Security are critical for retention. Users prefer:
- Fast load times
- Clear driver ratings and reviews
- Transparent pricing models
- Strict verification badges

OYD incorporates these findings by implementing lazy loading (conceptual), optimized React components for fast rendering, and prominent verification badges for approved drivers.

## 4. SOFTWARE REQUIREMENT SPECIFICATION (SRS)

### 4.1 Functional Requirements
- **User Registration/Login:** Users must be able to securely login via OTP.
- **Role Selection:** Dynamic switching between Admin, Driver, and Customer roles.
- **Trip Management:** Customers can input pickup, drop, and date details.
- **Driver Verification:** Admins must be able to approve or reject driver documents.

### 4.2 Non-Functional Requirements
- **Performance:** The site should load within 3 seconds.
- **Reliability:** Session data should persist across page refreshes.
- **Usability:** The interface must be intuitive for non-technical users.

### 4.3 Hardware Requirements
- Any standard PC or Laptop (i3/i5 Processor or above)
- 4GB RAM minimum (8GB recommended for optimal dev server running)
- Internet Connection for hosting and API fetching

### 4.4 Software Requirements
- **OS:** Windows / Mac / Linux
- **Browser:** Google Chrome / Firefox / Safari / Edge
- **Development Tools:** VS Code, Git, Node.js (v18+)

## 5. SOFTWARE SELECTION CRITERIA
The technology stack was chosen for its ubiquity, scalability, and performance:
- **React 18 & TypeScript:** For building robust, type-safe UI components, drastically reducing runtime errors.
- **Vite:** For a blazing-fast development server and optimized production build process (much faster than Create React App).
- **CSS3 & Lucide-React:** For custom styling, glassmorphism animations, and scalable vector icons without heavy framework overhead.
- **Axios & Fast2SMS:** For secure REST API communications and highly reliable OTP delivery.

## 6. PROJECT PLANNING
The project was executed in the following phased approach to ensure high quality and timely delivery:

1. **Requirement Gathering Phase:** Understanding what features are needed for a modern mobility app, researching competitor apps, and defining roles.
2. **Design Phase:** Creating the UI/UX architecture, defining the glassmorphism theme, establishing the color palette, and mapping out the user journey.
3. **Implementation Phase:** 
   - Setting up the React + Vite boilerplate.
   - Coding the reusable UI components (Typewriter, Layout, Navigation).
   - Establishing routing using React Router DOM.
   - Building out the complex role-based dashboards (Driver, Admin, Owner).
4. **Integration Phase:** Connecting the UI to the Fast2SMS OTP service and building the mock data layers to simulate a backend.
5. **Testing & QA Phase:** Verifying functionality across devices, checking responsive breakpoints, and ensuring no state leaks occur between roles.
6. **Deployment Phase:** Preparing the application for production build using Vite and optimizing asset delivery.

### 11.3 Secure SMS OTP Service (`src/services/sms.ts`)
The integration with the Fast2SMS API for sending OTPs securely using Axios.

```typescript
import axios from "axios";

// Environment variable protection for API keys
const FAST2SMS_API_KEY = import.meta.env.VITE_FAST2SMS_API_KEY || "YOUR_FAST2SMS_API_KEY_HERE";

// Toggle simulation mode automatically if key is missing (for dev environments)
const IS_SIMULATION = FAST2SMS_API_KEY === "YOUR_FAST2SMS_API_KEY_HERE";

interface SendOtpParams {
    phone: string;
    otp: string;
}

export async function sendOtp({ phone, otp }: SendOtpParams) {
    if (IS_SIMULATION) {
        console.log(`[SIMULATION] OTP ${otp} sent to ${phone}`);
        return { success: true, simulated: true };
    }

    try {
        const response = await axios.post(
            "https://www.fast2sms.com/dev/bulkV2",
            {
                route: "otp",
                variables_values: otp,
                numbers: phone,
            },
            {
                headers: {
                    authorization: FAST2SMS_API_KEY,
                    "Content-Type": "application/json",
                },
            }
        );

        return {
            success: response.data.return === true,
            data: response.data,
        };
    } catch (error: any) {
        console.error("Fast2SMS error:", error?.response?.data || error.message);
        return {
            success: false,
            error: "Failed to send OTP",
        };
    }
}
```

```tsx
                                <p>{driver.age} yrs • {driver.experience} Exp</p>
                            </div>

                            <div className="doc-status">
                                <div className="doc-item"><FileText size={14} /> License</div>
                                <div className="doc-item"><FileText size={14} /> Aadhaar</div>
                                {driver.docIssues && <span className="issue-tag">Doc Issues</span>}
                            </div>

                            <div className="actions">
                                {driver.status === 'pending' ? (
                                    <>
                                        <button className="btn-icon reject" 
                                                onClick={() => handleVerify(driver.id, 'rejected')}>
                                            <X size={18} />
                                        </button>
                                        <button className="btn-icon approve" 
                                                onClick={() => handleVerify(driver.id, 'verified')}>
                                            <Check size={18} />
                                        </button>
                                    </>
                                ) : (
                                    <span className={`status-badge ${driver.status}`}>
                                        {driver.status}
                                    </span>
                                )}
                            </div>
                        </div>
                    ))}
                </div>
            </div>
        </div>
    );
}
```

### 11.5 Custom Typewriter UI Component (`src/components/Typewriter.tsx`)
A custom React hook implementation to create the dynamic typing effect seen on the Home page hero section.

```tsx
import { useState, useEffect } from 'react';

export interface TypewriterSegment {
  text?: string;
  className?: string;
  isBr?: boolean;
}

interface Props {
  segments: TypewriterSegment[];
  typingSpeed?: number;
}

export function Typewriter({ segments, typingSpeed = 50 }: Props) {
  const [displayedText, setDisplayedText] = useState('');
  
  useEffect(() => {
    let currentIdx = 0;
    const textToType = segments.map(s => s.text || '').join('');
    
    const intervalId = setInterval(() => {
      setDisplayedText(textToType.substring(0, currentIdx + 1));
      currentIdx++;
      if (currentIdx === textToType.length) {
        clearInterval(intervalId);
      }
    }, typingSpeed);

    return () => clearInterval(intervalId);
  }, [segments, typingSpeed]);

  return (
    <span className="typewriter-container">
      {displayedText}
      <span className="cursor-blink">|</span>
    </span>
  );
}
```

## 16. COMMON ERRORS AND EXPLANATIONS
- **Invalid Mobile Number Length:** Thrown when a user attempts to request an OTP with a number shorter or longer than 10 digits. Protects API limits.
- **OTP Failed to Send:** Triggered when the Fast2SMS API key is invalid or API limits are reached. The app gracefully catches this and falls back to simulation mode if keys are absent.
- **Route Protection Bounce:** If a user logs in as 'Customer' but attempts to navigate directly to `/driver-dashboard` via URL, the system will block rendering and throw a permissions warning.

## 17. LIMITATIONS
- The current version relies on Local Storage or Mock State arrays rather than a persistent production database (like MongoDB/PostgreSQL).
- SMS Delivery is reliant on third-party API availability (Fast2SMS) and their regulatory compliance for DLT templates.
- Real-time GPS tracking is conceptualized in the UI but not yet functionally integrated with live Google Maps/Mapbox APIs.
