Gourmet  Go is a premium  food ordering  web application  designed  to bring  a high-quality 
user experience to online food delivery. The project aims to bridge the gap between 
hungry customers and high -quality restaurants through a seamless, visually enhanced 
digital interface.  
The application primarily focuses on user experience, of fering a sleek, dark -themed 
responsive  design  where  users  can browse  a categorized  menu,  add items  to a cart, and 
proceed to checkout. It solves the common problem of clunky, slow, or unattractive food 
ordering interfaces by utilizing modern web technologi es. 
 
1.1 Purpose  
 
The purpose  of this project  is to develop  a functional  prototype  of a food delivery  frontend 
that demonstrates proficiency in modern web development standards (HTML5, CSS3, 
JavaScript) and user interface design principles.  
 
1.2 Scope  
 
The scope  includes  the development  of the client -side interface,  including:  
 
 Home  Page  with Hero  Section  
 Interactive  Menu  with Categories  
 Shopping Cart  Functionality  
 User  Authentication  (Login/Signup  Simulation)  
 Responsive  Design  for Mobile  and Desktop  
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 
 2. SYSTEM  ANALYSIS  
The system  is designed  as a Single  Page  Application  (SPA)  feel using  standard  multi -page 
architecture. It relies on the client -side browser to hand le logic such as cart managemenand routing  between  pages.  
 
2.1 Existing  System  
 
Traditional food ordering often requires phone calls or visiting physical locations. Existing 
web solutions  can sometimes  be cluttered.  This system  simplifies  the process  into a visual - 
first approach.  
2.2 Proposed  System  
 
The proposed  system  automates  the selection  and calculation  process.  It provides  instant 
visual feedback (animations, cart updates) and ensures data persistence using Local 
Storage so users don't lose their cart if they refresh the page.  
 
 
 
 
3. LITERA TURE SURVEY  
A study of existing successful platforms like Zomato, Swiggy, and UberEats reveals that  
User Interface (UI) and User Experience (UX) are critical for retention. Users prefer:  
 Fast load times  
 Clear  imagery  
 Simple  checkout  flows  
Gourmet Go incorporates these findings by implementing lazy loading (conceptual), 
optimized CSS for fast rendering, and a "Cart Drawer" pattern popular in modern e - 
commerce.  
 
 
 
 
 
 
 
 
 
 
 
4. SOFTWARE  REQUIREMENT  SPECIFICATION  (SRS)  
4.1 Functional  Requirements  
 
 User  Registration/Login:  Users  must  be able to create  an account  and log in. 
 Browse  Menu: Users  must  be able to filter food items  by category.  
 Cart Management:  Add/Remove  items  and see total price.  4.2 Non-Functional  Requirements  
 
 Performance:  The site should  load within  3 seconds.  
 Reliability:  Cart data should  persist  across  sessions.  
 Usability:  The interface  must  be intuitive  for non-technical  users.  
 
4.3 Hardware Requirements  
 
 Any standard  PC or Laptop  (i3 Processor  or above)  
 4GB RAM  minimum  
 Internet  Connection  for hosting  
 
4.4 Software  Requirements  
 
 OS: Windows/Mac/Linux  
 Browser:  Google  Chrome  / Firefox  / Safari  
 Development  Tools: VS Code,  Git 
 
 
 
 
 
 
 
 
 
 
 
5. SOFTWARE  SELECTION  CRITERIA  
The technology  stack  was chosen  for its ubiquity  and performance:  
 HTML5:  For semantic  structure.  
 CSS3:  For styling,  animations,  and responsive  layout  without  heavy  frameworks.  
 JavaScript  (ES6+): For logic and DOM  manipulation.  
 
6. PROJECT  PLANNING  
The project  was executed  in the following  phases:  
1. Requirement  Gathering:  Understanding  what  features  are needed.  2. Design  Phase:  Creating  the UI/UX  mockups  and color  palette  selection.  
3. Implementation:  Coding  the HTML  structure,  then CSS styling,  then JS logic.  
4. Testing:  Verifying  functionality  across  devices.  
5. Deployment:  Hosting  the application  on GitHub  Pages.

15. COMMON  ERRORS  AND  EXPLANATIONS  
 404 Not Found: Occurs  if the hosting  URL is incorrect.  Solution:  Check  the GitHub 
Pages settings. 
 Images  not loading: Caused  by incorrect  file paths.  Solution:  Used  relative  paths 
(e.g., ./images/). 
 Form  Validation  Error:  If password  is too weak.  Solution:  Follow  the helper's  text 
instructions carefully. 
16. LIMITATIONS  
 No Backend:  Data  is stored  in the browser's Local  Storage,  so it is lost if the cache 
is cleared or a different device is used. 
 Static  Menu:  The menu  items  are hardcoded  in JavaScript;  there  is no Admin 
Panel to add new items dynamically without code changes. 
